# Collection collaboration rules

- This collection is the intended future Git root; the parent remains a local project collection. Four subprojects retain independent uv locks and environments. Read the selected subproject's AGENTS and research records before edits.
- Publish project-authored code and original curated text under MIT only. Preserve third-party attribution and exclude materials without compatible redistribution rights. Data, weights and historical source archives remain ignored.
- General publication methods belong in the user's collaboration/template vault; specific implementation and verification evidence belong here. All repository use must work without that external vault.
- Preserve scientific formulas, hypothesis statuses and negative results. Relocation checks establish implementation usability, not scientific validity.
- Use independent run IDs and retain failures. Keep public paths relative, avoid private identifiers, and synchronize English/Chinese public facts and commands.
- Do not automatically initialize Git, stage, commit, push, install hooks or modify Git configuration. Inspect actual staged files, identity and history when those operations are authorized.
