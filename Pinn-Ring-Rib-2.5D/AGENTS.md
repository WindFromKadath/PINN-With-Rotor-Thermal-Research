# 科研项目协作规则

- 接手先读 README.md、相关 hypotheses.csv 与 experiments.csv 行，再检查对应原文、配置、代码及原始结果；历史总结中的解释须回查依据。
- 用户要求和已采纳设计确定目标；实现说明计算过程；原始资料和结果支撑判断。来源矛盾时注明版本与适用范围。
- 作者视角由作者维护。可依据原文指出缺口，不能用实验完成或检查通过代替作者理解。
- 区分探索与验证实验。验证实验事先固定对象、评价、预算；结果出来后改变设计或指标须登记新运行及原因。
- 每次使用独立 run_id，保存配置、数据哈希、代码版本、环境、随机种子、日志、权重和结果；失败与负结果不得覆盖或筛掉。
- `completed` 只表示执行完成。假设支持程度另记，并限定证据与范围；重要研究结论由负责人确认，历史支持状态不等于本轮验证。
- 在用户已确定的范围与预算内自行修复普通错误；研究目标、关键物理设计或预算改变时说明影响，由用户决定。
- 更新既有 CSV 索引并在对话交接。入口长期文档保持 README.md 与 AGENTS.md；只有明确用途才另建研究报告。

## 本项目实现约束

- 最新用户要求：代码和模型可用，并保留加热/冷却各两组本地优选版本，即认为重构完成；无需完整复现指标。不要将重新长训或精度复现作为本次结案前置条件。版本包不上传 Git。

- 原项目和母模板是只读来源。新项目独立使用，运行代码不得依赖原目录、启动目录或个人机器绝对路径。
- 固定使用 uv、Python 3.12.14 和 uv.lock；CPU/CUDA extra 互斥，缓存为项目 `.cache/uv`。常规命令使用 `--locked`。
- 导入模块不得读取数据、加载权重或启动训练。DeepXDE 后端只在显式初始化时设置，采用 PyTorch。
- 主线为加热 v6.5 独立环 / v6 单向肋 / v6.5 耦合，与冷却 v6 硬初值版本。保留版本差异；不得把冷却 Lambda 替换为加热公式。
- 旧权重必须绑定模型包定义与变换，检查哈希并严格加载。新检查点必须包含整组三域网络、厚度网络、格式、配置和来源信息；不混用单域权重。
- 保留历史物理公式、无量纲尺度、抽稀顺序、连续肋编号训练域、快照上节点查询和交替训练顺序。物理疑点写入 README；修正需要独立配置和对照实验。
- 数据契约为 `r[m], theta[rad], t[s], True_T[K], thickness[m], rib_id[0..12]`。`True_T` 不能再次除厚度；COMSOL 积分温度须显式声明 `integral`。
- 配置路径相对 TOML 文件解析；实验设置放配置，不能编辑共享脚本切换参数。每次耦合用独立 CouplingState，不能引入全局快照。
- 验证针对计算与工作流程；短训练指标不能用来证明精度、收敛或替代 COMSOL。域平均温度与表面温度分别报告。
- 当前默认短示例：种子 42，厚度 100 步，三温度网络各 40 步，两轮耦合每域每轮 40 步，关闭 L-BFGS；短厚度训练从历史权重继续，学习率 1e-5，完整配置为原 1e-3。
- 修改数值逻辑后运行相应兼容检查，使用既定 `1e-3 K` 预测阈值与 PDE/BC `rtol=1e-4, atol=1e-5`，不得放宽判据迎合结果。
- 多执行者工作时各自独立 run_id，指定一位汇总者维护共享索引；当前任务未授权自动派生协作任务。

- 不自动提交、推送、安装 Hook 或修改 Git 设置。提交前检查完整暂存内容、署名；发布前另查拟发布历史与附件。
- 通用文档用相对路径，避免私人绝对路径和真实个人信息。原始来源路径参数只在本地迁移时提供。
