## 5. 数据迁移与契约

1. 建立完整外层文件清单：来源相对路径、大小、SHA-256、用途与复制状态。源码、原始数据、历史输出分别标记，原文件保持只读。
2. 复制必要 STL、主线 CSV、IWG 参考数据、小规模检查数据和精选模型。优先包含 HeatPINNCheck.csv、HeatPINNCheck_long.csv、ElsPINNTrain.csv、ElsPINNCheck_long.csv；按验证需要补充采样缓存、应力参照和宽表。
3. 约 5 GB 的 ElsMisesSCheck.csv 与非主线大文件默认建哈希索引，按需要显式复制，不将外部路径作为默认运行依赖。不具备所需应力参照时明确报告可得性。
4. 复制文件哈希逐项一致；重复数据仅在哈希及用途匹配时合并，不按文件名或大小去重。
5. 支持 COMSOL 宽表和已整理长表。读取真实 @t= 列头、表达式名和声明单位；缺少单位元数据时要求导入配置显式说明，不推测时间与温度单位。

统一内部物理字段为 x,y,z,r（m）、theta（rad）、t（s）、T（K）、u_r/u_z（m）、stress（Pa）。原 CSV 中 mm、μm 和温度单位显式转换；热网 5D 编码与力学 3D 编码由 profile 管理。保存源哈希、单位、参考量、时间轴、采样和划分规则。

大 CSV 分块读取、处理后按块缓存；模型评估分批，不一次将全量数据或计算图放入显存。训练/评价分别使用 42+i 与 99999+i 等来源约定；运行配置记录实际规则，不仅记录一个总 seed。

## 6. 模块化与运行入口

- 几何：STL 单位转换、体内拒绝采样、表面及界面采样、法向方向和边界标签。
- 物理：热扩散、无量纲往返、柱坐标角度链式法则、热弹性应变/应力和平衡方程；参数从 profile 进入。
- 模型：热网、瞬态/稳态力学网、MLP、IWG、X-PINN；导入不创建输出目录、不读数据、不加载权重、不训练。
- 耦合：冻结热网权重，同时保留输入空间导数。PDE 温度桥不使用 no_grad/detach 切断梯度。X-PINN 源侧通量计算完成后再按来源规则停止梯度。
- 训练：共享 Adam / L-BFGS、固定批次闭包、损失日志和独立状态；超参数不留在 main 内的隐式常量。
- 评估：绑定指定运行的模型、尺度、单位、对齐策略和点集；历史与新训练分别统计。

计划提供 thermo-rotor 命令：

| 子命令 | 用途 |
|---|---|
| preprocess / sample | 数据转换与几何采样 |
| train-thermal / train-mechanical | 热学训练、以指定热学运行作为温度桥的力学训练 |
| train-coupled | 按顺序完成单向热→力训练 |
| train-mlp / train-iwg / train-xpinn | 对照、刚体处理与稳态域分解 |
| predict / evaluate / plot / compare | 指定运行的预测、评价、图与比较 |
| demo | 对应 profile 的短流程 |
| legacy-evaluate | 严格重放指定历史模型包 |

新配置采用 TOML，数据路径相对配置文件解析；历史 YAML 原样归档。profile 与 runtime 分开，保存完整解析后配置，禁止引用旧目录和依赖启动位置。

每个运行使用独立 run_id；重复编号拒绝覆盖。记录命令、解析配置、源码版本/哈希、数据哈希、环境、种子、日志、检查点、预测、指标和图。失败保留异常与已有产物；不把缺数据的 dry-run 登记为训练 completed。

## 7. 精选历史模型包

目标是少数可用、来源清楚的版本，初定四类：

2. FXXKINGGOD 主线：独立的热学 + 匹配力学候选；固定权重/NTK 候选按匹配网络和有限诊断选择，不能与另一组热网混用。
3. IWG：约束法、投影法与各自对齐和 COMSOL 参考。
4. 统一 MLP 对照：1100 / 33k 数据量版本，与主线评价协议绑定。

正式热学/X-PINN 若无匹配旧权重，则交付代码、配置和新短训检查点，不虚构历史模型。具体保留数量由成功匹配的候选决定。

每包 model_spec.json 绑定格式版本、来源、网络定义、输入/输出变换、尺度、刚体对齐、温度桥、权重哈希和选择理由。保留原权重和必要源码；转换后的检查点只含张量与必要原生元数据。

先按来源指标筛选，再以固定小样本进行严格加载及有限预测诊断；候选排序注明样本与旧划分不确定性，不宣称全局最优。只允许可信且已核对的必要旧元数据类型，不执行归档训练脚本处理反序列化。

## 8. uv 环境

- 固定 Python 3.13.14，建立项目独立 .venv；不复用其他项目环境。
- pyproject.toml 显式声明 PyTorch、NumPy、pandas、SciPy、Matplotlib、PyYAML、trimesh、rtree；pytest 放 dev 组，notebook 依赖可选。早期 DeepXDE 路线只归档，首轮不将 DeepXDE、torchvision、torchaudio、Jupyter 作为必需依赖。
- 起步使用本机参考环境已有的 torch 2.14.1、numpy 2.5.3、pandas 3.0.6、scipy 1.18.1、matplotlib 3.11.2、PyYAML 6.0.3；trimesh/rtree 经实际安装及 STL 采样验证后写入锁定版本，不把尚未安装的软件标为验证完成。
- cpu / cuda extras 互斥；PyTorch 分别使用官方 CPU 和 cu130 索引。CPU 作为验收基线，CUDA 作小规模加载、导数、前后向及保存重载检查。
- uv 缓存配置为 .cache/uv，避免当前全局缓存权限问题；uv.lock 是环境依据，兼容 requirements 清单由锁文件导出，不通过 freeze 写入绝对 editable 路径。

实施后使用 uv sync --locked --extra cpu 与 uv run --locked --extra cpu；GPU 检查使用独立环境或重新同步 cuda extra，记录精确环境。

## 9. 实施顺序与短预算

阶段 A：填充模板、源码/数据来源清单、profile、uv 声明与锁文件，完成必要副本迁移及哈希核验。

阶段 B：先实现历史模型兼容加载、预测、评价与图，验证模型可用，再重写训练。

阶段 C：共享物理和网络模块 → 热学 → 温度桥/瞬态力学 → MLP 对照；保留两个工况独立尺度。

阶段 D：IWG 对齐与课程训练 → 正式热学配置 → 稳态 X-PINN 分域/界面；扩展分支保留索引。

阶段 E：运行实现测试、CPU 短流程、GPU 小检查；严格重载、单位/路径/覆盖失败检查；完成双语入口、来源包索引和实验登记。

短预算提案：seed=42；热学和力学各 Adam 40 步；域内 128 点、每类边界 64 点、IC 64 点；3 个时间片，每片最多 32 个数据锚点；主 demo 关闭 L-BFGS。IWG 每课程阶段 20 步，X-PINN 每阶段 20 步；MLP 两个短预算分别使用 32/96 标签，注明与原 1100/33k 不同。另用 1–2 次小规模 L-BFGS 外循环检查优化器路径，max_iter=5。

完整配置保留来源真实预算，参数优先级按现有代码核对；不照抄同时存在的 training/hybrid_training 注释而误认有效预算。本轮不执行完整训练，也不重跑大预算精度对照。

## 10. 验收

- 安装：uv sync --locked 成功，导入及命令帮助可用；不依赖旧项目 .venv。
- 迁移：已复制文件哈希匹配；主线默认运行只使用新目录内文件，从其他启动目录可运行。

- 耦合：热网权重不更新，输入导数非零且正确；时间尺度桥接一致；源模型/来源运行被明确绑定。

- 失败：缺文件、错误单位/列头、非法时间轴/几何、模型/尺度不匹配、非有限损失和重复 run_id 给出明确错误，失败记录保留。
