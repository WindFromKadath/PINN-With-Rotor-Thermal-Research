# 科研项目协作规则 · Neural-Operator-Reference

- 接手先确认用户当前问题，读取 README.md、相关 hypotheses.csv 与 experiments.csv 行，再检查有关原文、代码、配置及原始结果。历史总结中的解释要回查依据。
- 用户要求和已采纳设计确定研究目标；当前实现说明计算过程；原始资料和实验结果支撑具体判断。来源矛盾时注明各自版本与适用范围。
- 作者视角记录作者自己的研究理解与疑点。可对照原始证据指出错误和缺口，由作者理解后回写，不要代写；实验完成或复核通过不能证明作者已经理解研究链。
- 关键路线改变时说明依据变化、选择和后续验证（见 README.md「已采纳的关键取舍」D101+）。
- 区分探索实验和验证实验。验证实验先确定比较对象、评价与预算；看过结果后改变方案或指标时，登记新实验及改变原因。
- 按独立 run_id 保存原始输出和配置，不覆盖或筛掉失败及负结果。保留代码版本、数据版本、环境和随机种子（适用时）。
- 正确性检查针对计算与实现（tests/ 与 `problems`/`solvers` 的解析解对照）；实验结果用于检验假设。不得修改数据划分、预算、基线或指标来迎合预期而不记录变更。
- `completed` 表示实验执行完成，支持程度另在假设表中记录；支持、未获支持及无法区分都注明范围与证据。引用不能核实时标为待核实。
- AI 的解释和建议由证据约束，重要研究结论由负责人确认。已有解释影响本轮方案时回查原始结果；可复现仍需考虑偏差和替代解释。
- 在既定预算与范围内自行执行和修复普通错误；研究目标、关键设计或预算变化时，先说明影响，由用户决定。
- 更新已有假设和实验索引，在对话中交接。独立论文或实验报告有明确用途时才新建 Markdown，并从入口链接。
- 结案报告：实验编号、实际设置与版本、原始结果位置、对假设的有限判断、失败与局限、下一步验证。

## 本库特定约定

- 环境：Python 3.13.14 + uv；pyproject.toml 声明、uv.lock 锁定，使用互斥 cpu/cuda extras。依赖变更后更新 uv.lock，再导出兼容 requirements-lock.txt。
- 所有训练入口必须：设显式种子（config `seed` 字段）、写 `config.json`/loss 历史到 `artifacts/<run_id>/`、评估加载权重用 `strict=True`、数据集显式 train/eval 划分。
- 物理参数只允许出现在 `heatops/problems/` 与 configs 中；业务代码不硬编码物理常数与本地路径。
- 原档案库 `neural-operator-exploration` 为只读档案：可参考其代码与结论，不得修改；其数据与权重未入库；当前精选副本位于 local_reference_versions/，实际可得性回查本地索引。
- 上游 deeponet 官方仓库（CC BY-NC-SA 4.0）的逐字拷贝代码不得迁入本库（D102）。

## 隐私与提交

- 区分公开方法、可公开合成数据、受限制的原始数据和原始会话；引用文献不自动获得再发布原文、附件或第三方数据的权限。
- 文档与代码注释中不得出现真实姓名与盘符开头的本地绝对路径；本地数据位置统一写「未入库，本地归档」。
- 提交前核查完整暂存内容与署名，发布前另核查拟发布历史及附件；未核查材料保持待核验，不把实验完成当作公开批准。
- IDE 目录（`.idea/`、`.vscode/`）与 `.ipynb_checkpoints/` 由 .gitignore 排除；发现其中含本地路径或个人信息时不得恢复入库。

- 新运行必须显式使用未占用的 run_id。配置内数据路径相对配置文件；失败保留产物，不将数据缺失的 dry-run 标为训练完成。
- FNO 的 PDE/BC 使用输出场有限差分；解析场 autograd API 不适用于非局部算子的逐点物理导数。
- 历史模型按 model_spec.json 绑定网络和原变换，加载核验哈希与 strict=True；历史快照只读，不运行旧脚本。
- 当前验收仅要求参考代码与模型可用。短训完成不证明精度或收敛性；不自动代作者修改假设状态。
- 用户要求本地产物不上传 Git，不自动提交、推送、安装 Hook 或修改 Git 配置。
